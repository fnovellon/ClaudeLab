Tirage à variance minimale

Un algorithme qui garde un taux de succès théorique tout en éliminant les longues séries de malchance (ou de chance) — au prix de rendre le tirage presque entièrement déterministe après le premier coup.

Simulation interactive Comparaison Monte Carlo Vanilla JS, zéro dépendance

01Le principe

Idée de départ : on a un taux théorique p (ex. 20%). Plutôt que de tirer chaque coup indépendamment (ce qui peut produire de longues séries perdantes ou gagnantes), on corrige le tirage à chaque étape en comparant le taux réel observé au taux théorique.

1

Premier tirage

Le tout premier coup est un vrai tirage aléatoire : gagné avec probabilité p.

2

Calcul du taux actuel

Après chaque tirage, on calcule taux_actuel = victoires / tirages.

3

Correction

Si taux_actuel > p → on force une perte. Sinon (≤ p) → on force une victoire.

4

On boucle

Le taux actuel évolue à chaque coup et oscille étroitement autour de p, sans jamais s'en éloigner longtemps.

Conséquence intéressante : à partir du 2e tirage, la séquence est entièrement déterministe — seul le premier coup contient du hasard. Le résultat ressemble à une séquence à faible discrépance (dans l'esprit de l'algorithme de Bresenham) : les victoires se répartissent le plus régulièrement possible, espacées d'environ 1/p tirages.

03La variance, mesurée

Un seul run ne prouve rien. On répète l'expérience des milliers de fois pour comparer statistiquement la dispersion des deux méthodes, sur deux mesures : le nombre de victoires obtenues sur N tirages, et la plus longue série de pertes consécutives (le "drought").

04Le code

L'implémentation tient en quelques lignes.

function createBalancedDraw(p) {
  let count = 0;
  let wins = 0;

  return function draw() {
    let win;
    if (count === 0) {
      // premier tirage : vrai hasard
      win = Math.random() < p;
    } else {
      const currentRate = wins / count;
      // au-dessus du taux théorique -> on force une perte
      // sinon (<=) -> on force une victoire
      win = currentRate <= p;
    }
    count++;
    if (win) wins++;
    return win;
  };
}

const draw = createBalancedDraw(0.2); // 20%
draw(); draw(); draw(); // ...

05À garder en tête

Cet algorithme réduit la variance perçue mais rend la séquence prévisible : dès que le premier coup est connu, tous les suivants le sont aussi. Il ne convient donc pas aux contextes où l'imprévisibilité coup par coup est requise (jeux d'argent, sécurité), mais il est très utilisé dans le design de jeux vidéo pour lisser des taux de drop et éviter la frustration des "mauvaises séries" — souvent sous une forme assouplie (ex. en ne forçant qu'une tendance plutôt qu'un résultat strict, ou en ajoutant un peu de bruit résiduel).
